کارفرما پیشنهادهای ۱ تا ۹ را **تأیید کرد**. این تصمیم‌ها در `control/decisions/DECISION_LOG.csv` ثبت شده‌اند و هنگام راه‌اندازی مخزن خودکار اعمال می‌شوند. نیازی نیست دوباره `/decide` بزنید.
- **تکمیل DEC-002:** سامانه کاملاً تحت وب است و کاربران از مرورگر و به‌صورت آنلاین کار می‌کنند.

## ۱. DEC-001 + DEC-039 — فناوری اصلی (P0)
**پیشنهاد:** Django 5.2 LTS + Django REST Framework + PostgreSQL 17 برای Backend. React + TypeScript برای رابط کاربری. Celery + Redis برای کارهای زمان‌بر.
- **چرا:** این پروژه پر از نقش، دسترسی، تراکنش و گردش تأیید است. Django این‌ها را آماده دارد. پشتیبانی Django 5.2 تا آوریل ۲۰۲۸ ادامه دارد. نمونه FastAPI قدیمی کنار گذاشته می‌شود و فقط به عنوان مرجع خوانده می‌شود.
- **جایگزین:** FastAPI. سریع‌تر و سبک‌تر است، ولی دسترسی‌ها، پنل مدیریت و گردش کار را باید از صفر ساخت. این یعنی هزینه و ریسک بیشتر.
```
/decide DEC-001 APPROVED <نام شما> "Django 5.2 LTS + DRF + PostgreSQL 17 + React/TS + Celery/Redis؛ Modular Monolith"
/decide DEC-039 CLOSED <نام شما> "تعارض با انتخاب Django در DEC-001 بسته شد"
```

## ۲. DEC-002 — محل استقرار (P0)
**پیشنهاد:**
- یک سرور داخل شرکت با Ubuntu Server 24.04 LTS و Docker Compose.
- دو محیط جدا روی آن: Staging برای تست شما و Production برای پایلوت.
- محیط توسعه همان دو سیستم شما (ویندوز محل کار و اوبونتو خانه) است.
- دیتابیس به اینترنت وصل نیست.
- برای شروع سخت‌افزار تقریبی ۸ هسته، ۳۲ گیگ رم و ۵۰۰ گیگ SSD کافی است. این برآورد است و در فاز ۱۲ دوباره سنجیده می‌شود.
- **چرا:** داده کارخانه داخل شرکت می‌ماند و قطعی اینترنت، سالن تولید را متوقف نمی‌کند.
- **جایگزین:** سرور ابری داخلی (VPS). نگهداری ساده‌تر است، ولی داده بیرون از شرکت است.
```
/decide DEC-002 APPROVED <نام شما> "سرور داخلی Ubuntu 24.04 + Docker Compose؛ Staging و Production جدا؛ DB بدون دسترسی اینترنت"
```

## ۳. DEC-041 — مخزن مشترک برای کار از دو سیستم (P0، جدید)
**پیشنهاد:** یک مخزن **خصوصی GitHub** فقط برای کد، گزارش‌ها و فایل وضعیت. هیچ فایل خصوصی کارخانه، رمز یا داده مشتری در آن نیست و قفل pre-commit هم جلویش را می‌گیرد.
- **چرا:** بدون VPN از محل کار و خانه در دسترس است. هر دو سیستم با `git pull`/`git push` همگام می‌شوند و قفل کار نمی‌گذارد دو سیستم هم‌زمان کار کنند.
- **جایگزین:** Gitea روی سرور شرکت به‌همراه VPN (مثلاً WireGuard) برای خانه. کنترل کامل دست شماست، ولی راه‌اندازی VPN و نگهداری بیشتری لازم دارد.
- **سؤال از شما:** آیا سیاست شرکت اجازه می‌دهد کد (بدون داده) روی GitHub باشد؟
```
/decide DEC-041 APPROVED <نام شما> "GitHub private repo فقط برای کد/گزارش/وضعیت؛ داده خصوصی ممنوع"
```

## ۶. DEC-028 — دسترسی Claude Code به فایل‌های خام کارخانه (P0، مهم)
**نکته مهم:** Claude Code روی سیستم شما اجرا می‌شود، ولی هر چه بخواند برای پردازش به سرویس Anthropic فرستاده می‌شود. یعنی «محلی» به این معنی نیست که داده از شرکت بیرون نمی‌رود. شما همین فایل‌ها را در این گفت‌وگو هم آپلود کرده‌اید.

**پیشنهاد (حد وسط):**
- Claude Code فقط روی **سیستم محل کار** اجازه دارد فایل‌های برنامه‌ریزی، انبار، مهندسی، DXF و BOM را **بخواند**، برای تحلیل و ساخت تست‌های مرجع (Golden Test).
- برای تست‌ها فقط نمونه‌های **ناشناس‌شده** ساخته می‌شود و فایل خام هرگز وارد Git نمی‌شود.
- شیت‌ها یا ستون‌های **حقوق، قیمت فروش و اطلاعات تماس مشتری** خوانده نمی‌شوند.
- سیستم خانه پوشه خصوصی ندارد. تست‌هایی که فایل خام لازم دارند، فقط در محل کار اجرا می‌شوند.
- **جایگزین سخت‌گیرانه:** شما یا کارشناس IT خروجی ناشناس‌شده تهیه می‌کنید و Claude فقط همان را می‌بیند. امن‌تر است، ولی کار شما و زمان پروژه را بیشتر می‌کند.
```
/decide DEC-028 APPROVED <نام شما> "خواندن منابع برنامه‌ریزی/انبار/مهندسی فقط روی سیستم محل کار؛ بدون حقوق/قیمت/تماس مشتری؛ فیکسچر ناشناس؛ هیچ فایل خام در Git"
```

## ۱۰. DEC-042 — نسخه آنلاین کجا میزبانی شود؟ (P0، جدید)
چون همه کاربران باید آنلاین و از مرورگر کار کنند، باید معلوم شود سرور اصلی کجا باشد.

| | الف) سرور داخل شرکت + IP ثابت | ب) دیتاسنتر داخل ایران |
|---|---|---|
| وقتی اینترنت کارخانه قطع شود | سالن تولید از شبکه داخلی کارش را ادامه می‌دهد. فقط کاربران بیرون قطع می‌شوند. | سالن تولید هم قطع می‌شود (فقط ثبت آفلاین کمک می‌کند). |
| داده | داخل شرکت | بیرون از شرکت |
| نیازها | IP ثابت، دامنه، UPS، اینترنت پایدار | هزینه ماهانه، قرارداد با دیتاسنتر |

**پیشنهاد: گزینه الف برای پایلوت.** کاربر اصلی سالن تولید است و نباید با قطع اینترنت بخوابد. قواعد دسترسی:
- **همه** کسانی که از بیرون کارخانه وارد می‌شوند، ورود دومرحله‌ای دارند.
- حساب‌های اپراتور و ترمینال سالن فقط از شبکه داخلی کارخانه کار می‌کنند.
- پشتیبان طبق DEC-004 بیرون از سرور نگه داشته می‌شود.

بعد از پایلوت، با آمار واقعی قطعی و ترافیک، دوباره بررسی می‌شود.
```
/decide DEC-042 APPROVED <نام شما> "Production روی سرور داخلی با IP ثابت+دامنه+HTTPS؛ MFA برای همه ورودهای بیرون کارخانه؛ اپراتورها فقط از شبکه داخلی؛ بازبینی پس از پایلوت"
```
