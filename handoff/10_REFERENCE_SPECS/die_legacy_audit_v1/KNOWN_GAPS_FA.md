# نقص‌ها، ریسک‌ها و تصمیم‌های باز

**K-01 / بحرانی:** Blade List در رابط فعال اما در `find_the_path` شاخه BL پیاده‌سازی نشده؛ در نسخه جدید باید مسیر مستقل و آزمون‌پذیر داشته باشد.
**K-02 / بحرانی:** تابع صادرکننده لیست نهایی تیغه و ثبت در فایل پیگیری در منبع موجود نیست؛ آن را از روی BOM حدس نزنید.
**K-03 / بحرانی:** هیچ الگوریتم صدور کد ۱۴رقمی تیغه در این فایل یافت نشد؛ الزام کد از مستند/فایل پیگیری تیغه و تأیید قواعد می‌آید.
**K-04 / بالا:** خوشه‌بندی مبتنی بر ACI color و Bounding Box به‌تنهایی لزوماً یک تیغه فیزیکی مستقل را ثابت نمی‌کند؛ کاندیدا باید Review مهندسی داشته باشد.
**K-05 / بالا:** انتخاب DXF بر اساس mtime به جای Revision تأییدشده خطر داده اشتباه دارد.
**K-06 / بالا:** فایل‌های DXF نامعتبر، متن خالی، Bounding Box نامعتبر، زیرمجموعه‌های روی‌هم‌افتاده و گروه‌های چندگانه، مدیریت استثنا ندارند.
**K-07 / بالا:** مسیرها N: و Y: روی میزکار وابسته‌اند؛ در معماری جدید Canonical UNC path، تنظیمات و مجوز خواندن لازم است.
**K-08 / بالا:** درج در Excel و حذف فایل قبلی مربوط به BOM است؛ روی رجیستری تیغه نباید هیچ تخریب یا بازنویسی خام انجام شود.
**K-09 / متوسط:** رنگ و نوع موجودیت‌های دیگر مانند BLOCK/INSERT، XREF، LAYER vs entity color، BYLAYER/BYBLOCK در این منطق تضمین نشده‌اند.
**K-10 / متوسط:** کد محصول با صفر پیشرو باید String باشد؛ معتبر بودن کد ترکیبی از روی قواعد ۱۴رقمی مستقل بررسی شود.
**K-11 / متوسط:** تیغه موجود برای چند محصول و چند Revision می‌تواند مشترک باشد؛ رکورد فنی از نسخه‌های فیزیکی انبارک جدا بماند.
**K-12 / متوسط:** ترتیب، تعداد، واحدهای هندسی DXF، ابعاد، تلرانس، نتایج جستجوی تیغه مشابه و تأیید انسانی در این کد مشخص نیست و باید با قواعد کارخانه تعیین شود.
