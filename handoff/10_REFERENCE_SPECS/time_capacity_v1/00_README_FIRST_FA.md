# قرارداد طراحی موتور زمان‌سنجی و ظرفیت‌سنجی عالیخان — نسخه پیشنهادی 1.0

**وضعیت:** Specification برای بررسی و تحویل به Codex / Claude Code؛ **نه کد اجرایی**، نه زمان استاندارد قطعی و نه تصویب نهایی کارخانه.

## تصمیم‌های تثبیت‌شده بر اساس گفتگو
- چهار خانواده محصول: **کیف، کفش، کمربند، محصولات جیبی**.
- دو مسیر مهندسی برای هر سریال: طراحی جدید یا مهندسی تولیدِ محصول دارای الگوی تأییدشده.
- زمان‌ها و منابع باید به OPC و Revision مربوط باشند؛ سریال بدون نسخه فنی معتبر نباید بر اساس ظرفیت قطعی وعده داده شود.
- دو شیفت چرخشی و ظرفیت وابسته به نفر، ماشین و مهارت؛ الگوی نیروهای ۱۰/۱۲ نفر یک سابقه اعلام‌شده است، نه عدد ثابت سیستم.
- خطوط موازی: `LineType` و `LineInstance` جدا؛ تغییر اختصاص سریال بین خطوط نیازمند تأیید برنامه‌ریزی.
- خروجی عملکرد باید در **واحد استاندارد معادل (SWU)** هم قابل مشاهده باشد، نه فقط شمارش قطعه.
- فایل آماده زمان‌سنجی/ظرفیت‌سنجی وجود ندارد؛ بنابراین زمان‌های عملیاتی، ضریب مجاز، ضریب عملکرد و نرخ هدف را جعل نمی‌کنیم.
- ساخت نرم‌افزار با Codex/Claude Code انجام می‌شود؛ نقش این بسته تعیین قرارداد، قواعد و آزمون‌هاست.

## ساختار تحویل
1. `01_FAMILY_ROUTES_FA.md`: عملیات مرجع چهار خانواده، اختیاری/اجباری و دروازه‌های کیفیت.
2. `02_TIME_STUDY_STANDARD_FA.md`: پروتکل ثبت مشاهده، نسخه‌بندی، تایید زمان استاندارد.
3. `03_CAPACITY_AND_SWU_FA.md`: مدل نفر، ماشین، خط، شیفت، WIP، برنامه‌ریزی و SWU.
4. `04_DOMAIN_MODEL_API_EVENTS_FA.md`: موجودیت‌ها، ناوردایی‌ها، API و رویدادها.
5. `05_UI_AND_PERMISSIONS_FA.md`: نقشه صفحات از کاتالوگ ۵۲ صفحه‌ای و تعاملات.
6. `06_SECURITY_PRIVACY_FA.md`: امنیت/محرمانگی/تقلب/ثبت تغییرات.
7. `07_TEST_ACCEPTANCE_FA.md`: تست‌های نمونه و شرط تحویل فاز.
8. `08_PHASE_HANDOFF_FA.md`: ترتیب اجرای توسعه برای Codex/Claude Code و قالب گزارش.
9. `09_DECISIONS_OPEN_FA.md`: مسائل نیازمند تأیید کارخانه پیش از Activation.
10. `10_SCENARIO_EXAMPLES_FA.md`: سناریوهای فرضیِ ریاضی، نه زمان استاندارد.
11. `ENGINE_CONTRACT.json`: قرارداد ساختاری پیشنهادی برای توسعه‌دهنده.
12. `data_collection_csv/`: قالب‌های خام CSV با کدگذاری UTF-8 BOM، قابل بازکردن در Excel، **بدون زمان استاندارد از پیش‌ساخته** (XLSX در این اجرا به‌دلیل اختلال ابزار تولید نشد).

## قوانین انتشار زمان و برنامه ظرفیت
- `DRAFT` یا `UNDER_STUDY` را هرگز به‌عنوان استاندارد مصوب یا ظرفیت قطعی نمایش نده.
- هر استاندارد باید به `Product/Style` یا خانواده + شرایط هم‌ارز + عملیات + Revision + روش اجرا + پیکربندی نفر/ماشین و واحد خروجی متصل باشد.
- تغییر مواد/دستگاه/ابزار/الگو/روش ساخت ممکن است مستلزم بازسنجی باشد؛ همه استانداردهای تاریخی حفظ می‌شوند.
- هر تصمیم محاسباتی قابل ردیابی: ورودی، نسخه محاسبه، بازه، نوع تقویم، معیار و Approval.

## مرزبندی فاز
موتور زمان‌سنجی در محدوده **فاز مهندسی/OPC** آغاز می‌شود و موتور ظرفیت در **فاز برنامه‌ریزی** بر پایه استانداردهای منتشرشده ساخته می‌شود. ثبت زمان واقعی با ترمینال اپراتور/تولید متصل خواهد شد. نباید صدور زمان استاندارد موکول به پیاده‌سازی تمام ۵۲ صفحه شود.
