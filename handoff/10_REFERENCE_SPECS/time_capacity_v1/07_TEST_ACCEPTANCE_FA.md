# ۷. سناریوهای پذیرش — Gherkin-ready، غیرکدنویسی

## داده و مطالعه
**TC01 — هیچ زمان جعلی**: Given هیچ استاندارد منتشرشده‌ای برای Style/Revision نیست، When Planner Commit می‌زند، Then `NO_APPROVED_STANDARD` و Block Commit یا مسیر Exception مصوب نمایش داده شود؛ عدد ۰ یا نرخ خانوادگی به جای استاندارد نشیند.

**TC02 — ثبت وقت به واحد صحیح**: Given یک فرآیند تک‌نفره و ثانیه قابل‌قبول، When مشاهدات ثبت می‌شود، Then زمان فعال نفر، اشغال ماشین و انتظار جدا و واحدها محفوظ بمانند.

**TC03 — نفر همزمان**: Given دو نفر همزمان روی یک عملیات با زمان‌های درگیری متفاوت کار کرده‌اند، When نفر-دقیقه محاسبه می‌شود، Then مجموع زمان واقعی درگیری نفرها ملاک باشد، نه ضرب ثابت روی طول کل بچ.

**TC04 — داده پرت/متفاوت**: Given ثبت غیرعادی، When پالایش می‌شود، Then حذف از محاسبه فقط با Reason/Approval و Raw Observation باقی بماند.

**TC05 — استاندارد نسخه‌دار**: Given STD v1 منتشر شده و STD v2 اصلاحی تصویب می‌شود، When برنامه قبلی باز می‌شود، Then با Snapshot v1 باقی بماند و تغییرات v2 فقط روی برنامه جدید/بازبرنامه‌ریزی تأییدشده اعمال شود.

**TC06 — زمان Setup**: Given دو بچ متفاوت از یک Style، When مدت محاسبه می‌شود، Then setup دوبار برای دو بچ ثبت می‌شود؛ با تقسیم setup بر تعداد واحد، نمایش KPI per unit مجاز است ولی برنامه واقعی setup را جدا نگه دارد.

**TC07 — خشک‌شدن**: Given عملیات رنگ لبه با زمان انتظار روی قفسه، When ظرفیت نفر/ماشین حساب می‌شود، Then انتظار نفر-دقیقه/ماشین-دقیقه ایجاد نکند مگر resource rack محدود یا ماشین واقعاً اشغال است؛ Lead Time افزایش یابد.

## ظرفیت / برنامه‌ریزی
**TC08 — دستگاه مشترک**: Given یک ماشین مشترک برای کیف و کمربند، When دو سفارش همزمان برنامه‌ریزی می‌شوند، Then جمع بازه اشغال منابع از available تجاوز نکند و دو خط یک ماشین را همزمان نگیرند.

**TC09 — انتقال نیرو**: Given اپراتور از خط A به B منتقل می‌شود، When Scenario حل می‌شود، Then ظرفیت A کاهش یابد، B افزایش یابد و اثر خالص نشان داده شود؛ Approval لازم است.

**TC10 — عدم صلاحیت**: Given اپراتور آموزش لازم برای ماشین را ندارد/منقضی است، When Solver اجرا می‌شود، Then این تخصیص انتخاب نشود.

**TC11 — تعمیرات**: Given ماشین در تقویم تعمیرات است، When Scheduler اجرا می‌شود، Then capacity آن بازه صفر یا اشغال‌شده لحاظ شود و بازبرنامه‌ریزی انجام شود.

**TC12 — تقویم شیفت‌ها**: Given شیفت‌های چرخشی با استراحت و مرخصی، When capacity محاسبه می‌شود، Then Available دقیقاً مطابق calendar-effective و بدون دوباره‌شماری شخص/ماشین باشد.

**TC13 — WIP و اقلام Holding**: Given بچ در QC Hold یا کمبود ماده است، When برنامه Release می‌شود، Then Start این عملیات Block و دلیل/مالک مشکل مشخص شود.

**TC14 — Solver Timeout**: Given محدودیت زمان حل فرا می‌رسد، When solver متوقف می‌شود، Then نتیجه FEASIBLE/UNKNOWN جداگانه و میزان Gap یا دلیل ثبت شود؛ قطعی/بهینه اعلام نشود.

## عملکرد و صحت شمارش
**TC15 — SWU یکتا**: Given یک Event تکمیل عملیات دوبار ارسال شده، When ledger ingest می‌شود، Then فقط یک بار standard-minute credit ثبت شود.

**TC16 — بازکاری**: Given خروجی در QC رد شده و به بازکاری برگشته، When مجدداً تکمیل می‌شود، Then خروجی نهایی خوب یک بار شمرده شود و بازکاری زمان/هزینه مجزا داشته باشد.

**TC17 — کفش جفت/تک**: Given ۲ تک‌لنگه یک جفت را تشکیل می‌دهند، When output ثبت می‌شود، Then conversion مصوب اعمال شود؛ دو لنگه به‌عنوان دو جفت محاسبه نشود.

**TC18 — استاندارد مشروط به Style**: Given دو کیف با متریال/جزئیات متفاوت، When Standard Resolve می‌شود، Then عدم انطباق شرایط به جای استفاده خودکار از میانگین خانواده گزارش شود.

**TC19 — ظرفیت پیشنهادی و مصوب**: Given استاندارد پیشنهادی تأیید نشده، When صفحه مدیریتی نمایش می‌یابد، Then آن را در ستون پیش‌بینی غیرقطعی با برچسب نشان دهد و Commit دکمه غیرفعال باشد.

## امنیت و استقرار
**TC20 — منع دسترسی حقوق**: Given ادمین فنی یا اپراتور، When API دستمزد/عملکرد محرمانه HR را فراخوانی می‌کند، Then 403 + Audit و هیچ اطلاعات حساسی برنگردد.

**TC21 — مسیر تأیید**: Given یک نفر خودش مطالعه را ایجاد و تکمیل کرده، When همان نفر می‌خواهد به‌عنوان Approval دوم منتشر کند، Then Separation of Duties اعمال شود.

**TC22 — تحمل قطع شبکه**: Given اپراتور عملیات را شروع کرده و شبکه قطع می‌شود، When بازمی‌گردد، Then رویدادها با Idempotency Sync شوند و بازه‌های موازی/تکراری برای بررسی Flag شوند.

**TC23 — CSV Injection**: Given فیلد متنی با `=cmd` یا `+HYPERLINK`, When خروجی Excel/CSV تولید می‌شود, Then به صورت متن خنثی صادر شود.

**TC24 — تست یکپارچه E2E**: ثبت Product/Style/Revision -> OPC و Time Study -> Approval -> Capacity Scenario -> Shift Allocation -> Production Start/Finish -> QC -> SWU -> Dashboard؛ انحراف هر مرحله باید قابل ردیابی باشد.

## شرط قبولی فاز
- Coverage گزارش‌شده برای Core Domain, Calculations, Security, Permissions؛ درصد آستانه توسط مسئول QA در فاز صفر تعیین شود، نه ساختگی.
- Migration و Rollback، Load test مطابق بار واقعی کارخانه، Incident Drill، Backup Restore و ۴ تست Responsive.
- نمایش evidence برای همه ۲۴ سناریو + Screenshot UI + API Examples + Seed synthetic data که با داده واقعی اشتباه نشود.
- فاز با Bug بحرانی/بالا، ناسازگاری داده یا نداشتن Approval رسمی بسته نمی‌شود.
