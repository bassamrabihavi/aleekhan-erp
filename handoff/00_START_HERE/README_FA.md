# عالیخان | بسته مرجع نهاییِ شروع توسعه — Handoff v1.0

**وضعیت:** DEVELOPMENT HANDOFF BASELINE (آماده تحویل برای آغاز فاز صفر). این عنوان به معنی «تمام قواعد کارخانه، API و UI از قبل تأیید شده» نیست. ۵۲ صفحه پیش‌نویس‌اند و نقاط باز در Decision Register کنترل می‌شوند. تاریخ مبنا: ۱۴۰۵/۰۸/۱۰ / 2026-11-01.

## برای چه کسانی؟
- **Codex / Claude Code:** تنها مجری کدنویسی و آزمون و مستندسازی خروجی در مخزن توسعه.
- **ChatGPT در گفت‌وگو با کارفرما:** معمارِ مرجع/ممیز خروجی و نگارنده ایراد و تصمیم؛ *نباید به‌جای عامل کدنویسی، محصول را پیاده‌سازی کند*.
- **مالک فرآیند کارخانه:** تصویب قواعد کارخانه، آزمون عملی و پذیرش Gate.

## راه شروع دقیق (۵ گام)
1. فایل‌های `AGENTS.md` و `CLAUDE.md` در ریشه را بخوان. سپس `00_START_HERE/DECISION_AND_PRECEDENCE.md` و `01_ARCHITECTURE/ADR_001_TECH_STACK.md`.
2. `03_PHASE_PLAN/PHASE_00.md` را بخوان. **فقط فاز ۰** را اجرا کن. بدون اعلام Gate قبلی، فاز بعد را شروع نکن.
3. پیش از کدنویسی هر فاز: اثر بر مدل داده، معماری، امنیت و داده‌های واقعی را در گزارش تحلیل کن. قواعد باز را خودسرانه قطعی نکن.
4. در پایان هر Step، از `04_AGENT_WORKFLOW/DEVELOPER_REPORT_TEMPLATE.md` گزارش با شواهد بده؛ تست، Migration، Snapshot UI، شناسه commit و مشکلات باز را ضمیمه کن.
5. کارفرما گزارش/تغییرات را برای ChatGPT می‌فرستد؛ ممیزی طبق `04_AGENT_WORKFLOW/REVIEW_CHECKLIST.md` با نتیجه **PASS / REWORK / BLOCKED** برمی‌گردد. فقط با تأیید کتبی Gate بعدی باز می‌شود.

## تعریف «کامل» در هر فاز
هر فاز باید دیتابیس، API/Backend، موتورهای محاسباتی همان دامنه، UI فارسی RTL دسکتاپ/موبایل، امنیت، Import/Export مرتبط، تست واحد/یکپارچه/E2E، مستندات و Runbook داشته باشد؛ در صورت نیاز فاز به موتور خاص، «وجود ندارد» باید شفاف در خروجی و گیت ثبت شود، نه با فایل نمایشی جایگزین شود.

## خط قرمزهای فرآیندی
- کد **۱۴رقمی** راهکاران **رشته** است؛ صفرهای ابتدایی و نوع کد محفوظ.
- کد محصول/استایل، کد تیغه، شناسه کلیشه و **شماره سریال** هرکدام هویت مستقلی دارند.
- هر خط سفارش = یک Product/Style و یک Serial؛ سفارش مادر چند ردیف مجاز دارد. سریال می‌تواند Batch/Bundle متعدد داشته باشد.
- داده‌های خام Excel/DXF همراه نام فایل، Hash، Sheet، Cell، Formula، Snapshot و Import Run باید قابل ردیابی باشند.
- موجودی راهکاران مرجع رسمی **Snapshot** است؛ سیستم مالک رزرو، وضعیت فیزیکی و QA Hold است؛ جمع‌زدن اشتباه رزرو با موجودی ممنوع.
- **Python DXF فقط لیست تیغه را استخراج و به جریان جدول پیگیری تیغه می‌فرستد؛ کد ۱۴رقمی و شرح تیغه در جدول پیگیری/تطبیق راهکاران به دست می‌آید.** فایل Python در دسترس، مسیر کامل این جریان را نشان نمی‌دهد؛ در تصمیم‌های باز ثبت شود.
- استاندارد زمان و SWU هنوز مقادیر/سیاست تأییدشده عمومی ندارند؛ مقدارهای پیشنهادی فقط `UNAPPROVED` هستند.
- تغییر گرید، درخواست خرید، تأیید مشتری، خروج انبار، دریافت فیزیکی و ارسال، مالک و مجوز متفاوت دارند.
- UIهای فعلی PROTOTYPE/DRAFT هستند و جایگزین تست عملی یا قبول نهایی نیستند.

## حفاظت از داده‌ها
شاخه `09_PRIVATE_FACTORY_SOURCES` شامل فایل‌های داخلی، ممکن است اطلاعات حساس/اسناد مشتری/ماکرو داشته باشد. **بدون تأیید کارفرما، این پوشه را به مخزن عمومی، سرویس AI خارجی یا ابزار CI شخص ثالث آپلود نکن.** فقط در محیط خصوصی مورد تأیید تحلیل کن؛ XLSM/Python قدیمی را خودکار اجرا نکن؛ فایل‌های موجود را تغییر نده. رمز عبور منابع را نه در Repository بنویس و نه در Log/Prompt.
