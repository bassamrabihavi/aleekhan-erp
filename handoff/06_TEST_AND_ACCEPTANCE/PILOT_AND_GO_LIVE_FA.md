# پایلوت واقعی و شرایط بهره‌برداری

## Pilot rehearsal
1. انتخاب واحدها، کاربران و سریال‌های مجاز و نسخه داده از مالک کارخانه؛ ثبت خط پایه رسمی راهکاران و نسخه فایل‌های Planning/WH.
2. اجرای parallel run: ثبت سفارش، کد/استایل/سریال، نسخه فنی، BOM/OPC، رزرو، برش، WIP، QA/QC، دریافت FG، ارسال جزئی، بستن سریال.
3. ثبت اختلاف هر مرحله در Case با شناسه رکورد، منبع، Timestamp، اسکرین‌شات، انتظار/واقعی، خطر مالی/تولیدی، severity، مسئول، fix commit.
4. آزمون روزانه با خود اپراتور و سرپرست، دسترسی، زمان پاسخ، قطع شبکه، import دیرهنگام، محدودیت ماشین، گرید/کیفیت و چاپ.
5. تست بازیابی از خرابی/Backup و قطع Job در محیط staging؛ نتایج مستند.

## Go / No-Go
- صفر Issue بحرانی P0 و عمده P1 حل‌نشده، یا استثنای **مکتوب** مسئول معتبر برای P1 غیرحساس با محدودسازی دامنه. هر خطای integrity/security P0 همیشه No-Go.
- تمامی واحدهای Commercial, Engineering, Planning, Warehouse, Production, QA/QC, Dispatch, IT, Security امضای Gate مربوط داشته باشند؛ مدیرعامل/مدیر کارخانه مجوز Go-Live.
- Source of Truth در cutover تعریف و زمان‌بندی شود؛ تغییر راهکاران هیچگاه بی‌موافقت و ADR انجام نشود.
- Rollback rehearsed با حفظ داده، restore verified، پشتیبانی/خدمات/آموزش و فرایند گزارش Incident فعال باشد.

## شاخص‌های Pilot برای اندازه‌گیری (بدون هدف ساختگی)
- نرخ خطای Import/شکست تطبیق، کسری موجودی قبل و بعد، اختلاف WIP، مدت ثبت اپراتور، وضعیت خط/صف، تاخیر تعهد، تغییرات BOM و ابزار، پاسخ سرویس و حوادث امنیتی.
- Target quantitative values باید از Baseline کارفرما در Phase-12/13 تصویب شوند؛ agent حدس نزند.
