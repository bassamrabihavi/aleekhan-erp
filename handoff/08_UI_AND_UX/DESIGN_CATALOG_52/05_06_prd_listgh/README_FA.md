# سراجی سنتی عالیخان — بسته طراحی شماره ۵ و ۶

## محدوده
- صفحه ۵: **برگه تولید پویا (Prd.Form)**
- صفحه ۶: **لیست قطعات برش (listGH)**
- تب‌های مرجع مقدماتی: **هدر انبار/جداسازی WH** و **تیغه و کد راهکاران** (به عنوان صفحات مستقل هنوز قفل نشده‌اند).
- از فایل‌های اصلی `Planning--.xlsm` و `WH-.xlsm` با رمز دریافتی کاربر، و فایل `جدول پیگیری تیغه.xlsx` برای استخراج هدر و نمونه‌ها استفاده شد. فایل‌های اصل هیچ تغییری نکرده‌اند و نسخه بازگشایی‌شده آن‌ها در این بسته قرار ندارد.

## مبنای واقعی منبع و یافته‌ها
1. `Planning--.xlsm → Prd.Form!B1`: `Form Code : FO-BG-03-07`، `B2`: `Aleekhan Code : 02050461660001`، `F1`: `برگه تولید اکسسوری`، `G1`: `62253`.
2. نمونه هدر `Prd.Form`: برند `شکوفامنش`، نماینده مشتری `خانم رهبری`، تعداد سفارش `5`، کد محصول `6166`، استایل `0001`، پروژه راهکاران `060003`، خط `جیبی` و WBS02 `سری تولید`.
3. `Planning--.xlsm → listGH!B11:M11`: توضیحات؛ جنس آستر؛ لیست قطعات آستر؛ توضیحات تیغه؛ تیغه؛ ترکیب برش؛ چاپ؛ کروپن؛ تعداد برش؛ قطعات برش چرم؛ چک؛ ردیف (ترتیب فیزیکی اکسل از B به M). نما به صورت RTL از ردیف آغاز می‌شود.
4. `WH-.xlsm → WH!A1:M1`: کاتالوگ کد و شرح کالا/واحد/طبقه/ماهیت و سایر مشخصات. `Split DB!A1:AY1`: داده‌های تفصیلی جداسازی شامل سریال، کد محصول، استایل، ردیف ماده، واحد، ضریب، موجودی، کسری، تحویلی، بازکاری، برگشتی، شناسه سند راهکاران و کنترل‌های دیگر. `کانبان!B6:P7`، `Split Form!D4:BG8` و `Gap!A4:H4` هم مبنا هستند.
5. `جدول پیگیری تیغه.xlsx`: شیت `Sheet3!M` کد عالیخان ۱۴رقمی و `Sheet3!P` شرح عالیخان؛ `Code search!H:K` کد، شرح عالیخان، شرح راهکاران و پرچم مغایرت؛ `خروجی تیغه راهکاران` کد و شرح رسمی.
6. **کد ۱۴رقمی محصولات** در Planning مشاهده شد. **کد ۱۴رقمی تیغه‌ها** نیز در فایل پیگیری با نمونه `05020121450110` مشاهده شد، اما الگوریتم تخصیص رقم‌ها برای تمام انواع تیغه هنوز آزمون نشده است.

## ویژگی نمونه HTML
- متن فارسی واقعی و جهت RTL؛ سایدبار ثابت در سمت راست، Hover و Pin در دسکتاپ، Drawer در موبایل.
- متریال‌های پویا به شکل آرایه: افزودن بی‌حد خرجکار، آستر یا ماده دیگر؛ جابه‌جایی و حذف ردیف؛ جنس، رنگ، چاپ، فینیش، واحد، ضریب و پرت اختصاصی.
- تب لیست قطعات برش با ستون‌های مستند منبع و افزودن نامحدود قطعه.
- تب معرفی هدرهای WH/Split DB و تب کنترل کد و شرح تیغه.
- چاپ آزمایشی و خروجی JSON آزمایشی.
- نمونه نمایشی «یک چرم اصلی + پنج خرجکار + دو آستر» فرض کاربر است و داده واقعی سریال ۶۲۲۵۳ نیست.

## محدودیت‌ها و کارهای قطعی باقیمانده
- **Pixel-perfect Print Reproduction:** محتوای هدر اصلی مبنا قرار گرفته؛ اندازه/مرج/بخش‌بندی چاپ `Prd.Form` و `listGH` هنوز باید با تصاویر چاپ مستقیم اصل Excel هم‌سنجی شود.
- **Parity VBA & Formula:** فرمول‌ها و ماکروهای همه عملیات ثبت/چاپ/انتقال داده هنوز به‌طور کامل به زبان الگوریتم مستقل تبدیل و آزمون نشده‌اند.
- **WH Import:** استخراج عنوان‌های مرجع صورت گرفته؛ همه رکوردهای WH هنوز به دیتابیس واقعی منتقل یا Reconcile نشده‌اند.
- **API/DB:** نمونه HTML هیچ ارتباطی با دیتابیس ندارد. تمام ذخیره‌سازی فعلاً در حافظه مرورگر است و فقط فایل JSON نمونه خروجی می‌دهد.
- **قواعد SKU/کد تیغه:** نمونه‌های واقعی استخراج شده‌اند، اما تخصیص/تکرار/استثناهای صدور کد در همه خانواده‌ها باید با داده تاریخی آزمون پاریتی شود.
- **تأیید طراحی:** این دو صفحه هنوز از سوی کاربر پیکسل‌به‌پیکسل تأیید نشده‌اند.

## الزام بدون اتلاف داده
برای هر Import، سه لایه مجزا طراحی شود: `raw_import_file` (بایت فایل و Hash)؛ `raw_import_cell` (sheet, address, type, raw, formula, format)؛ `normalized_records` (شناسه قابل جستجو/گزارش، version, provenance). هیچ مقدار مجهول، ۰ مبهم، رشته `*` یا ستونی که مقصد شناخته‌شده ندارد حذف یا خودکار Null نشود؛ به `UnmappedField`/`QualityIssue` برود.

**قانون مهم:** تعداد «چرم اصلی»، «خرجکار»، «آستر» و هر نوع مواد در Schema نباید ستون‌های ثابت ایجاد کند؛ هر نقش یک `material_spec_line` مستقل دارد و شماره‌گذاری ۱/۲/… فقط در لایه نمایش تولید می‌شود.
